title: "Configuration reference"
description: "Every environment variable ClaudeSec reads, and what it does."
---

All configuration is **optional** — ClaudeSec runs with sensible defaults and zero config. Set these as environment variables before starting the server (or the background service). Sensitive values are masked in the in-app reference. See `.env.example` for a copy-paste template.

## Server & networking

| Variable | Default | Purpose |
|----------|---------|---------|
| `CLAUDESEC_PORT` / `PORT` | `3000` | Dashboard + OTLP listen port |
| `CLAUDESEC_HOST` | `127.0.0.1` | Bind address. Set `0.0.0.0` only for deliberate LAN access |
| `CLAUDESEC_TOKEN` | — | Bearer token required for **non-loopback** API/MCP access; **required** to bind a non-loopback host (the server refuses to start otherwise). Loopback access is exempt |
| `CLAUDESEC_TRUST_LOCAL` | — | Set `1` to disable the loopback-address auth check and trust all clients (opt-in; default off). Use **only** when host exposure is already restricted — e.g. Docker with a `127.0.0.1`-only port binding |
| `CLAUDESEC_CORS_ORIGINS` | `localhost` | Comma-separated allowed CORS origins |
| `CLAUDESEC_TRUST_PROXY` | — | Set `1` to trust `X-Forwarded-For` (behind a reverse proxy) |
| `NODE_ENV` | — | `production` serves the built `dist/`; otherwise Vite dev mode |

## Storage & data safety

| Variable | Default | Purpose |
|----------|---------|---------|
| `CLAUDESEC_DB` | `~/.claudesec/spans.db` | SQLite database path (absolute; the resolved path is **logged at boot**). Point throwaway / test instances elsewhere to isolate them |
| `CLAUDESEC_ALLOW_RESET` | — | Must be `1` to permit `POST /api/reset`; the destructive data-wipe is disabled by default |
| `CLAUDESEC_SEED_DEMO` | — | Set `1` to seed an **empty** database once with synthetic demo sessions on startup. Used by the isolated demo container; never touches a database that already has data |
| `CLAUDESEC_NO_AUTOSTART` | — | Set `1` to make importing `server/index.ts` side-effect-free — no HTTP listener, no timers, no hook-config mirror writes. Used by tests and tooling that import the module without running the server |

## Enforcement

These configure the opt-in [Enforcement](/security/enforcement) PreToolUse hook. The mode is normally set from the **Enforce** dashboard tab (which the server mirrors to `enforce-config.json`); the env vars are the fallback.

| Variable | Default | Purpose |
|----------|---------|---------|
| `CLAUDESEC_MODE` | `monitor` | Hook mode: `monitor` logs would-blocks (default), `enforce` blocks high-severity tool calls |
| `CLAUDESEC_HOOKS_BYPASS` | — | Set `1` in the hook's environment to allow everything for one invocation (escape hatch). Best-effort recorded in the enforcement feed so the bypass is auditable, not silent |
| `CLAUDESEC_ALLOW_LOCAL_FETCH` | — | Set `1` to let a `WebFetch` reach loopback / private (RFC1918) ranges in `enforce` mode (e.g. a local dev server). Cloud-metadata and link-local addresses stay blocked regardless. See [SSRF on fetch](/security/enforcement#ssrf-on-fetch) |
| `CLAUDESEC_ENFORCE_CONFIG` | `enforce-config.json` | Path to the mirrored enforce-config file the hook reads (fail-open if absent) |
| `CLAUDESEC_ENFORCE_RULES` | `rules-enforcement.json` | Path to the compiled block-rule snapshot the hook and MCP proxy evaluate against |
| `CLAUDESEC_PROTECTED_PATHS` | `<hooksDir>/protected-paths.json` | Path to the protected-paths list the hook reads (fail-open if absent) |
| `CLAUDESEC_HOME` | `~/.claudesec` | ClaudeSec home directory where the installed hook and its rule/path artifacts live |
| `CLAUDESEC_CLAUDE_SETTINGS` | `~/.claude/settings.json` | Path to the Claude Code settings file `claudesec install-hook` merges the PreToolUse entries into |

## MCP / skill scanner

| Variable | Default | Purpose |
|----------|---------|---------|
| `CLAUDESEC_MCP_SCAN_ROOTS` | `~/.claude` | Colon/comma-separated roots for the [MCP & skill scanner](/security/mcp-scan). **Replaces** the defaults (does not append) |

## Local watcher

| Variable | Default | Purpose |
|----------|---------|---------|
| `CLAUDESEC_WATCH` | `1` | Local transcript watcher. `0` disables it (OTLP still works) |
| `CLAUDESEC_BACKFILL` | `0` | `1` imports each transcript's full history on first sight, not just new lines |

## Detection & privacy

| Variable | Default | Purpose |
|----------|---------|---------|
| `CLAUDESEC_DISABLE_SCRUB` | — | Set `1` to store raw, unscrubbed attributes (not recommended) |
| `CLAUDESEC_HONEYTOKENS` | — | Comma-separated canary strings; any span containing one fires a HIGH exfiltration alert |
| `CLAUDESEC_JUDGE_URL` | — | Optional [LLM-as-judge](/how-to/local-llm) endpoint (OpenAI-compatible `/chat/completions`; e.g. local Ollama `http://localhost:11434/v1`). **Unset = off, no outbound calls.** Loopback allowed; non-loopback is SSRF-guarded |
| `CLAUDESEC_JUDGE_MODEL` | `llama3.1` | Model name passed to the judge endpoint |
| `CLAUDESEC_JUDGE_KEY` | — | Optional bearer key for the judge endpoint (not needed for local Ollama / LM Studio) |
| `CLAUDESEC_JUDGE_TIMEOUT_MS` | `8000` | Per-request judge timeout in milliseconds (capped at 60000) |

## Retention

| Variable | Default | Purpose |
|----------|---------|---------|
| `CLAUDESEC_MAX_SPANS` | `50000` | Soft span-count ceiling; reclaims only out-of-window spans above this |
| `CLAUDESEC_RETENTION_DAYS` | `183` | Age-based pruning threshold (~6 months, the EU AI Act minimum) — a hard floor count-pruning never crosses |

## Performance & limits

| Variable | Default | Purpose |
|----------|---------|---------|
| `CLAUDESEC_RATE_LIMIT_RPS` | `50` | Max OTLP requests/second per IP |
| `CLAUDESEC_RATE_LIMIT_BURST` | `200` | Token-bucket burst capacity |
| `CLAUDESEC_MAX_SPANS_BATCH` | `500` | Max spans allowed per OTLP batch |
| `CLAUDESEC_GRAPH_LIMIT` | `2000` | How many of the most-recent spans the live graph renders. Older spans are **not** deleted — they stay available via Search and Sessions. See [Data retention](/explanation/retention) |
| `CLAUDESEC_ORCH_LIMIT` | `20000` | How many of the most-recent spans the orchestration (spawn-tree) view queries |

## Alerts & integrations

| Variable | Default | Purpose |
|----------|---------|---------|
| `CLAUDESEC_WEBHOOK_URL` | — | Slack / Discord / generic JSON endpoint for alert delivery |
| `CLAUDESEC_WEBHOOK_THRESHOLD` | `high` | Minimum severity to webhook |
| `OTEL_FORWARD_URL` | — | Transparent OTLP proxy target (SSRF-blocked for private ranges) |
| `CLAUDESEC_AUTO_EXPORT_DIR` | `./exports` | Directory for hourly auto-export JSON snapshots |

## Remote / CI agent telemetry (set on the *agent*, not ClaudeSec)

These configure the **agent** to export OTLP to ClaudeSec — only needed for [remote or CI agents](/how-to/remote-agents), never for local capture.

| Variable | Purpose |
|----------|---------|
| `OTEL_EXPORTER_OTLP_ENDPOINT` | Point at `http://<host>:3000/v1/traces` |
| `OTEL_EXPORTER_OTLP_PROTOCOL` | Set to `http/json` |
| `CLAUDE_CODE_ENABLE_TELEMETRY` | Opt Claude Code into telemetry |
| `CLAUDE_CODE_ENHANCED_TELEMETRY_BETA` | Add model name + token counts |
| `OTEL_LOG_TOOL_DETAILS` | Add tool names + input arguments |
| `OTEL_LOG_TOOL_CONTENT` | Include full tool input/output bodies |
| `OTEL_LOG_RAW_API_BODIES` | Include raw Anthropic Messages API JSON |
