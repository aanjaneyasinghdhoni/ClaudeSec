ClaudeSec is zero-config. You do not set any environment variables, edit your shell profile, or restart your agents. Clone the repo, run it, and the dashboard fills with live agent activity.

## Prerequisites

- **Node.js 22.13+** (Node 22 LTS recommended)
- **pnpm** — managed automatically via corepack (run `corepack enable`)
- At least one supported agent on your machine — [Claude Code](/harnesses/claude-code), [GitHub Copilot CLI](/harnesses/copilot), or [Codex](/harnesses/codex)

<Note>
  `better-sqlite3` builds a native module on install. If you hit a build error, install the Xcode Command Line Tools (macOS) or `build-essential` (Linux) and try again.
</Note>

---

## Step 1 — Clone and run

The fastest path is the one-command starter — it installs dependencies, builds and serves the production app (zero-config) in the foreground, and tells you which agents it can see:

```bash
git clone https://github.com/aanjaneyasinghdhoni/ClaudeSec.git
cd ClaudeSec
./start.sh
```

Prefer to run the steps yourself? Install, then either build and serve the production app (what `./start.sh` does) or run the dev server with hot reload:

```bash
corepack enable
pnpm install
pnpm build && pnpm start   # production build, served from dist/
# or: pnpm dev              # dev server with hot reload
```

This starts the dashboard at **http://localhost:3000** and begins tailing every Claude Code, Copilot CLI, and Codex session on your machine.

Because your agents already write transcripts to disk, the dashboard fills with **real, live activity immediately** — including sessions that were running before you started it.

---

## Step 2 — Look around

Open [http://localhost:3000](http://localhost:3000) (it opens automatically). Within seconds of any agent action you'll see:

- A session row per trace, tagged with the harness that produced it.
- Spans appearing in the **Timeline** as colored bars, with live durations.
- **Alert** counts incrementing whenever a detection rule matches.

Take the [dashboard tour](/explanation/dashboard-tour) to learn what each screen is for.

---

## Step 3 — Check status from the terminal

```bash
node cli/init.mjs status      # server health, span/session/alert counts, uptime
node cli/init.mjs tail        # stream new spans live in your terminal
node cli/init.mjs processes   # list running agent processes
```

See the [CLI reference](/reference/cli) for every command.

## Run as a background service

`pnpm dev` runs in the foreground. To keep ClaudeSec running across reboots, build the dashboard once and install the user-level background service (launchd on macOS, systemd user service on Linux, a Scheduled Task on Windows) through the bundled CLI:

```bash
pnpm build
node cli/init.mjs            # install + start the service, open the dashboard
node cli/init.mjs stop       # stop and remove the service
```

Installing the service also removes any legacy ClaudeSec OTEL config it finds — the watcher needs none. Your data in `~/.claudesec/spans.db` is left untouched; to wipe stored data, run `node cli/init.mjs reset`.

## Try it with synthetic data (demo container)

Want to explore the dashboard, or show it to someone, without exposing your real telemetry? Start the **demo container** — a separate, on-demand container pre-seeded with synthetic data on its own isolated volume:

```bash
./start.sh --demo                  # brings up prod (:3000) AND demo (:3001)
# or, equivalently:
docker compose --profile demo up
```

This starts **two** containers side by side:

- **Prod** on **http://localhost:3000** — your real data, unchanged.
- **Demo** on **http://localhost:3001** — three synthetic sessions that fire real detection rules (RCE via `curl | bash`, SSH private-key read, dotenv read, POST exfiltration).

The demo container has its **own** database volume holding nothing but synthetic data, so it is **physically isolated** from your real data — there is no in-app toggle and no per-row tagging to get wrong. Override the demo port with `DEMO_PORT`. A plain `docker compose up` (or `./start.sh --docker`) never starts the demo service; it lives behind a Compose `demo` profile.

## Platform support

| Platform | Background service | Status |
|---|---|---|
| macOS | launchd LaunchAgent | **Verified** |
| Linux | systemd user service | Experimental |
| Windows | Scheduled Task (at logon) | Experimental |

The watcher and dashboard run anywhere Node ≥ 22.13 runs; only the auto-start *service* layer is platform-specific. On any platform you can always run the foreground server with `pnpm dev`.
