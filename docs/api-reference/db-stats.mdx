## Overview

The Database Stats API exposes SQLite health metrics (size, row counts, oldest/newest session) and lets you manually trigger pruning or adjust retention settings. Retention is enforced both by age (days) and by span count.

## Endpoints

### GET /api/db-stats

Get database statistics and current retention configuration.

```bash
curl http://localhost:3000/api/db-stats
```

**Response:**
```json
{
  "spansTotal": 1245,
  "sessionsTotal": 12,
  "alertsTotal": 38,
  "dbSizeBytes": 524288,
  "dbSizeHuman": "512.0 KB",
  "oldestSession": "2026-04-01T08:00:00.000Z",
  "newestSession": "2026-04-09T14:32:00.000Z",
  "retentionConfig": {
    "maxSpans": 1000000,
    "retentionDays": 183,
    "profile": "minimum",
    "profileLabel": "Minimum",
    "sources": { "retentionDays": "default", "maxSpans": "default" },
    "envOverride": null,
    "effective": {
      "limitingFactor": "age",
      "effectiveWindowDays": 183,
      "spansPerDay": 3545,
      "projectedSpansInWindow": 648735,
      "ingestStopsAtSpans": 900000,
      "ingestStopsAfterDays": 253,
      "estimatedBytes": 1751584500,
      "warning": null
    }
  }
}
```

`effective` reports what the configuration actually delivers at this install's own measured ingest rate. `limitingFactor` is `age` when the day window governs, `capacity` when the span ceiling stops ingestion first (in which case `warning` explains it and `effectiveWindowDays` is the real number of days), `none` for unbounded retention, or `unknown` when there is not yet enough history to measure a rate. `sources` says whether each value came from an environment variable, the dashboard, or the profile default — an environment variable overrides a value saved from the dashboard, and `envOverride` says so when that happens.

### GET /api/db-stats/retention/profiles

List the retention profiles and what each would deliver here, at the measured ingest rate.

```bash
curl http://localhost:3000/api/db-stats/retention/profiles
```

### POST /api/db-stats/prune

Manually trigger pruning. Removes sessions older than the configured retention period and trims excess spans beyond the max count.

```bash
curl -X POST http://localhost:3000/api/db-stats/prune
```

**Response:**
```json
{
  "status": "ok",
  "prunedByAge": 120,
  "prunedByCount": 0
}
```

`prunedByAge` is the number of spans removed because their session was older than `retentionDays`. `prunedByCount` is the number of oldest spans removed to stay under `maxSpans`.

### POST /api/db-stats/retention

Update retention policy settings.

**Request body:**
```json
{
  "maxSpans": 100000,
  "retentionDays": 14
}
```

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `profile` | string | No | `minimum`, `audit-year`, `forensic`, or `custom`. A named profile sets both values at once |
| `maxSpans` | number | No | Maximum number of spans to keep (minimum: 100) |
| `retentionDays` | number | No | Number of days to retain sessions (minimum: 1) |

All fields are optional; only provided fields are updated. Prefer a profile — setting the day window alone is what leaves a span ceiling too small to reach it. Settings can also be controlled via `CLAUDESEC_MAX_SPANS` and `CLAUDESEC_RETENTION_DAYS` environment variables (env vars take precedence over anything saved here).

**Response:**
```json
{
  "status": "ok",
  "profile": "custom",
  "maxSpans": 100000,
  "retentionDays": 14,
  "warning": null
}
```

The response also carries an `effective` object in the same shape as `GET /api/db-stats`, so a save that produces an unreachable window says so immediately instead of silently.

**Errors:**
- `400` — `maxSpans` below 100, `retentionDays` below 1, or an unknown `profile`
