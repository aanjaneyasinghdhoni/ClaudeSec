## Overview

The operator audit log is a tamper-evident, append-only record of every config-mutating or
security-relevant action taken through the ClaudeSec API: enforcement mode changes, rule
enable/disable, honeytoken updates, suppression creation, and more.

There is intentionally **no delete endpoint**. An audit log that can be cleared from the UI is
not an audit log. Retention is managed server-side — the oldest rows are pruned automatically
when the table exceeds its configured cap, so the log stays bounded without operator
intervention.

The log is ordered newest-first and supports cursor pagination via the `before` parameter.

## How "tamper-evident" works

Each row is **hash-chained** to the previous one: a row's hash is computed over its content plus
the hash of the row before it. Editing or deleting any earlier row breaks every hash from that
point on, so a recomputation can pinpoint the first row that no longer matches. By default the
chain is a plain SHA-256. If a local key file exists at `~/.claudesec/audit-key` (minted
owner-only on first run when writable), the chain is an HMAC-SHA256 keyed by that secret instead.

<Note>
  **Honest limitation — tamper-*evident*, not tamper-*proof*.** The chain makes after-the-fact
  edits *detectable*; it does not make them *impossible*. Without the HMAC key, anyone with write
  access to the database could rewrite a row and recompute the rest of the chain. The local key is
  the unforgeability backstop — keep it readable only by the owner, and back it up separately if
  you rely on it.
</Note>

## Endpoints

### GET /api/audit-log

Return a page of audit log entries, newest first.

```bash
curl "http://localhost:3000/api/audit-log?limit=25"
```

### Query parameters

| Parameter | Type | Default | Description |
|---|---|---|---|
| `limit` | integer | `100` | Number of entries per page; maximum `500` |
| `before` | integer | — | Cursor for pagination: return only entries with `id` less than this value |

To paginate, pass the `nextBefore` value from one response as `before` in the next request.

**Response:**

```json
{
  "entries": [
    {
      "id": 42,
      "ts": 1749600300000,
      "actor": "operator",
      "action": "enforce.config",
      "target": "enforce.config",
      "detail": "{\"mode\":\"enforce\",\"overrides\":{}}",
      "sourceIp": "127.0.0.1"
    },
    {
      "id": 41,
      "ts": 1749600120000,
      "actor": "operator",
      "action": "rule.disable",
      "target": "Bash — repeated large output",
      "detail": "{\"label\":\"Bash — repeated large output\",\"enabled\":false}",
      "sourceIp": "127.0.0.1"
    },
    {
      "id": 40,
      "ts": 1749599800000,
      "actor": "operator",
      "action": "honeytokens.set",
      "target": "honeytokens",
      "detail": "{\"count\":2}",
      "sourceIp": "127.0.0.1"
    }
  ],
  "total": 42,
  "nextBefore": 40
}
```

| Field | Description |
|---|---|
| `entries` | Array of audit log entries for this page |
| `entries[].id` | Auto-incrementing row ID (use as cursor) |
| `entries[].ts` | Unix timestamp in milliseconds |
| `entries[].actor` | Who performed the action (currently always `"operator"`) |
| `entries[].action` | Machine-readable action key, e.g. `enforce.config`, `rule.disable`, `honeytokens.set` |
| `entries[].target` | The resource that was affected |
| `entries[].detail` | JSON string with action-specific detail (honeytoken values are never included) |
| `entries[].sourceIp` | IP address of the request |
| `total` | Total number of entries in the log |
| `nextBefore` | ID to pass as `before` to fetch the next page, or `null` when this is the last page |

### Pagination example

```bash
# First page
curl "http://localhost:3000/api/audit-log?limit=25"

# Next page (use nextBefore from the previous response)
curl "http://localhost:3000/api/audit-log?limit=25&before=40"
```

### GET /api/audit/verify

Recompute the [hash chains](#how-tamper-evident-works) for **both** append-only logs — the
operator audit log and the persisted [enforcement feed](/api-reference/enforcement-api) — and
report whether each is intact. This is a read-only check; it never mutates anything.

```bash
curl http://localhost:3000/api/audit/verify
```

**Response:**

```json
{
  "ok": true,
  "audit":   { "ok": true, "rows": 42, "hashedRows": 42, "signed": true },
  "enforce": { "ok": true, "rows": 18, "hashedRows": 18, "signed": true }
}
```

| Field | Description |
|---|---|
| `ok` | `true` only when **both** chains verify |
| `audit` / `enforce` | Per-log result |
| `*.ok` | Whether this chain is intact |
| `*.rows` | Total rows scanned |
| `*.hashedRows` | Rows that participate in the chain (rows that predate hashing are skipped) |
| `*.signed` | `true` when an HMAC key is in use (otherwise a plain SHA-256 chain) |
| `*.brokenAtId` | Present only on failure — the `id` of the first row whose stored hash no longer matches a recomputation, i.e. where the log was tampered with |
